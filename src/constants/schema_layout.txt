/*
KEY RELATIONSHIP PATTERNS:
══════════════════════════

1. GEOGRAPHIC HIERARCHY (1:N at each level):
   COUNTRY → ZONE → STATE → TERRITORY
                  → STATE → DISTRICT → TALUKA → VILLAGE

2. PROJECT HIERARCHY:
   PROJECT → PROJECT_YEAR → PROJECT_YEAR_SEASON_MAPPING
   PROJECT → CROP_PROJECT → CROP_PROJECT_SEASON_MAPPING

3. FARMER CORE (Star schema around FARMER_DETAIL):
   FARMER_DETAIL ←→ FARMER_BANK_DETAIL (1:1)
   FARMER_DETAIL ←→ FARMER_AADHAAR_DETAIL (1:1)
   FARMER_DETAIL ←→ FARMER_AGREEMENT (1:N per project year)
   FARMER_DETAIL ←→ FIELD_DETAIL (1:N)
   FARMER_DETAIL → VILLAGE_MASTER (N:1)
   FARMER_DETAIL → STATE_MASTER (N:1)

4. FIELD-LEVEL DATA (linked to FIELD_DETAIL):
   FIELD_DETAIL ←→ CENSUS (1:N per season)
   FIELD_DETAIL ←→ POLYGON_QC_AUDIT (1:N)
   FIELD_DETAIL ←→ POLYGON_CHILD_MAP (1:N)
   FIELD_DETAIL ←→ PRACTICE_ADOPTION_DETAIL (1:N)
   FIELD_DETAIL ←→ PRACTICE_DOS_DETAILS (1:N)
   FIELD_DETAIL ←→ RS_PRACTICE_VALIDATION (1:N)
   FIELD_DETAIL ←→ TBL_SHORT_SURVEY (1:N)
   FIELD_DETAIL ←→ TBL_LONG_SURVEY (1:N)

5. ACTIVITY TRACKING:
   ACTIVITY_MASTER → ACTIVITY (1:N)
   ACTIVITY → (CENSUS, AGREEMENT, ATTESTATION, etc.) - referenced via ACTIVITY_ID

6. STATUS LIFECYCLE:
   STATUS_MAPPING_GROUP_MASTER → STATUS_MAPPING_MASTER → STATUS_MAPPING_REASON_MASTER
   STATUS_MAPPING records farmer status changes with reasons

7. USER/AGENT MANAGEMENT:
   ROLE_MASTER → USER_MASTER_EX (1:N)
   PARTNER_MASTER → USER_MASTER_EX (1:N)
   USER_MASTER_EX → ALLOTMENT_MASTER → VILLAGE_MASTER (assignment)

COMMON COLUMN PATTERNS:
═══════════════════════
- IS_ACTIVE (BOOLEAN): Soft delete flag present in ALL tables
- CREATED_AT/UPDATED_AT: Application-level timestamps
- CREATED_BY/UPDATED_BY: User who made the change
- IS_MIGRATED (BOOLEAN): Whether record was migrated from legacy system
- EDW_INSERTED_TIMESTAMP/EDW_UPDATED_TIMESTAMP: ETL pipeline timestamps
- All IDs are TEXT type (UUIDs) except some legacy NUMBER IDs in survey tables

REPORTING TIPS:
═══════════════
- For farmer counts: Always filter IS_ACTIVE = TRUE
- For project-year scoping: Join via PROJECT_YEAR_ID
- For geographic rollups: Join Village → Taluka → District → State → Zone
- For practice tracking: TBLFK_RS_PRACTICE_VALIDATION has RS model predictions
- Census is the largest transactional table (3.7M rows) - filter by season
- TBL_SHORT_SURVEY (4.2M rows) is the highest-volume table
- POLYGON_QC_AUDIT (2M rows) tracks all QC decisions on field polygons
